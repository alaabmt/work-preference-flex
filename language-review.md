# Bilingual Language Review Standard — V17

## Principle
Arabic and English are conceptually equivalent versions, not literal translations. Each version was written to sound natural to a professional participant in that language.

## Arabic standard
- Contemporary professional Modern Standard Arabic.
- Short, realistic workplace situations.
- Direct wording that can be understood across sectors.
- Avoid unnecessary project-management jargon and translation-like phrases.
- One observable action per option where possible.
- Similar option length, register, and desirability.
- Test used during review: **هل سيقول موظف عربي هذه الجملة فعلًا في بيئة عمل، أم تبدو وكأنها ترجمة؟**

## English standard
- Natural professional English rather than literal rendering of Arabic syntax.
- Avoid inflated corporate language and technical jargon unless the scenario requires it.
- Use concrete verbs and a single behavioral emphasis per option.
- Keep options parallel and professionally plausible.

## Structural audit completed
- Every preference item has exactly U/S/A in both languages.
- Every social item has TASK/SOC in both languages.
- Every needs block has identical need codes across languages.
- Every Flex item has identical U/S/A codes across languages.
- Because both languages live in one JSON record per item, key drift between language files is structurally prevented.

## Validation still required
Natural-language review does not prove measurement equivalence. Formal bilingual expert review, cognitive interviews, desirability studies, and later DIF/invariance analyses are still required before equivalent-score claims.
